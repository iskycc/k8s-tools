# k8s-tools

JDK8 + Maven 实现的 k8s 数据获取工具：

1. 通过 **SSH(Apache MINA SSHD) 登录 k8s master 节点**，检查/创建专用 ServiceAccount 并获取其 **永久 token**（`kubernetes.io/service-account-token` Secret，不过期）；**SA 已存在但拿不到 token 时自动先删除再重建**；
2. **自动发现 API Server 地址**、带回集群 CA 证书；
3. 使用该 token 通过 **k8s API**（Bearer 认证 + HTTPS，**自动忽略自签名证书**）获取集群数据：版本、节点、命名空间、Pod、Service、Deployment 等。

> 无真实集群时可直接运行本仓库的 **E2E 模拟测试**：内嵌 SSH 服务器模拟 master 节点（kubectl 输出）、
> 内嵌 HTTPS 服务器模拟 kube-apiserver（自签名证书 + Bearer Token 校验），覆盖完整链路与异常路径。

## 环境

- JDK 8+（本仓库以 `--release 8` 编译，产物为纯 Java 8 字节码）
- Maven 3.6+

## 构建与测试

```bash
mvn test       # 编译 + 运行全部单元测试与 E2E 模拟测试
mvn package    # 打包应用 jar（target/k8s-tools-1.0.0-SNAPSHOT.jar）
mvn dependency:copy-dependencies -DincludeScope=runtime  # 复制运行时依赖到 target/dependency/
```

## 对真实集群使用

```bash
java -cp 'target/k8s-tools-1.0.0-SNAPSHOT.jar:target/dependency/*' \
  com.iskycc.k8s.Main \
  --host <master-ip> --user root --password '***' --namespace default
```

应用 jar 不包含第三方依赖，运行前需要完成上面的依赖复制步骤。
Windows 下请使用双引号包裹 classpath，并将分隔符 `:` 改为 `;`。
可选参数包括 `--port 22`、`--api-server https://x.x.x.x:6443`、`--insecure`；
使用私钥时，将 `--password '***'` 替换为 `--key ~/.ssh/id_rsa`。

或作为库调用：

```java
SshConfig cfg = SshConfig.builder()
        .host("10.4.4.8").username("root").password("***").build();

// 1) SSH 到 master 创建或复用 ServiceAccount，读取其 Secret 中的永久 token
MasterInfo info = new ServiceTokenFetcher(cfg).fetch();

// 2) 用 token + 集群 CA 构建 API 客户端
K8sApiClient client = K8sApiClient.fromMasterInfo(info);

System.out.println(client.getVersion().getGitVersion());
client.listNodes().forEach(System.out::println);
client.listPods("default").forEach(System.out::println);
client.listServices("default").forEach(System.out::println);
client.listDeployments("default").forEach(System.out::println);
```

## SA 检查与永久 token 获取策略

`ServiceTokenFetcher` 在 master 上依次执行（全部可通过 `Options` 配置）。
`kubernetes.io/service-account-token` 类型 Secret 中的 token 由 token controller 签发，**永久有效、不过期**：

1. **检查 SA 是否已存在**：`kubectl -n kube-system get sa k8s-tools`，不存在则 `kubectl create serviceaccount`；
2. 获取永久 token：
   - 老集群(<1.24)：SA 自动生成过 token secret（`get sa ... jsonpath={.secrets[0].name}`）→ 直接读取复用；
   - 本工具此前创建的手动 secret 已有 token → 直接复用（幂等重跑）；
   - **SA 已存在但以上都拿不到 token → 先 `kubectl delete sa`（连带清理残留 secret）再重建**，
     然后走全新流程（可用 `recreateSaWhenTokenUnobtainable(false)` 关闭该行为，关闭时直接抛异常）；
   - 全新流程：`kubectl create secret generic k8s-tools-token --type=kubernetes.io/service-account-token`
     （AlreadyExists 容忍）→ `kubectl annotate secret ... kubernetes.io/service-account.name=k8s-tools --overwrite` 绑定 SA
     → 轮询 `get secret ... -o jsonpath={.data.token}` 等待 controller 填充（重试次数/间隔可配），本地 base64 解码；
3. `kubectl create clusterrolebinding k8s-tools --clusterrole=cluster-admin --serviceaccount=kube-system:k8s-tools`（已存在则忽略）。

## API Server 地址自动发现

依次尝试（`apiServerOverride` 可跳过发现）：

1. `kubectl config view --minify -o jsonpath={.clusters[0].cluster.server}`
2. `awk '/server:/{print $2; exit}' /etc/kubernetes/admin.conf`（路径可配 `kubeConfigPath`）
3. 兜底：`https://<ssh-host>:6443`

## TLS / 自签名证书处理

`K8sApiClient` 默认**不会因为自签名证书而失败**：

- master 上拿到 `ca.crt` → 先用集群 CA 严格校验；**校验失败（自签名/过期/主机名不匹配等）自动降级为 trust-all 透明重试**（`tlsAutoFallback`，默认开启，可关闭恢复严格模式）；
- master 上拿不到 CA → 直接跳过证书校验（`fromMasterInfo` 默认行为）；
- `--insecure` / `insecureSkipTlsVerify(true)` → 始终跳过校验；
- `isDegradedToInsecure()` 可查询是否发生过自动降级。

## E2E 测试覆盖

| 用例 | 验证内容 |
| --- | --- |
| `e2e_freshCluster_createSaAndPermanentToken_thenCallApi` | 全新集群：SA 存在性检查→创建→永久 secret（controller 延迟填充重试）→CA 校验调 API→全部资源数据断言→kubectl 命令序列与 Bearer 头断言 |
| `e2e_legacyCluster_reuseAutoGeneratedSecretToken` | 老集群：直接复用 SA 自动 secret，不 create/annotate/delete |
| `e2e_rerun_reuseExistingManualSecret_andApiUrlFromAdminConf` | 幂等重跑：复用已有手动 secret；kubeconfig 损坏时 API 地址自动从 admin.conf 发现 |
| `e2e_brokenSa_deletedAndRecreated_thenPermanentTokenObtained` | **SA 存在但 token 不可得 → 删除 SA 重建**；残留 secret AlreadyExists 容忍；API 地址三层全失败 → host:6443 兜底 |
| `e2e_brokenSa_recreateDisabled_throws` | 关闭自动重建时明确抛异常且不删 SA |
| `e2e_selfSignedCert_ignoredByTlsAutoFallback` | **错误 CA → TLS 校验失败 → 自动降级忽略自签名证书**，请求成功且 `isDegradedToInsecure()=true` |
| `e2e_noCaFromMaster_defaultsToInsecure_andWorks` | 无 CA 时默认忽略自签名证书 |
| `e2e_strictTls_failsWhenAutoFallbackDisabled` | 显式关闭降级后严格模式仍然生效 |
| `e2e_sshWrongPassword_fails` | SSH 密码错误 → 明确异常 |
| `e2e_apiInvalidToken_returns401` | 非法 token → 401 及响应体 |
| `e2e_apiUnknownPath_returns404` | 未知路径 → 404 |
| `MainDemoTest` | CLI 入口对模拟集群完整执行三步流程 |
| `K8sApiClientTest` | Builder 参数校验、URL 规范化、MasterInfo token 掩码 |
